# Модули

Модуль — это часть, подключённая к плате проводами: дисплей, считыватель, датчик, лента светодиодов.
Самостоятельной платой он не является: плата программы называет его в `modules`, с шиной, к которой он
подключён, и его пинами. Страница пишет такую плату для комплекта с модулями. В `examples/local_boards` она
написана руками: круглый дисплей на QSPI и символьный LCD 2004 на переходнике I2C PCF8574, оба — модули
программы.

## В плате программы

```json
"buses": { "i2c": { "i2c0": { "sda": 4, "scl": 5 } } },
"modules": {
    "text": {
        "module": "lcd2004_pcf8574",
        "on": { "i2c.i2c0": {} },
        "supply": { "VCC": "5V" },
        "devices": { "lcd": { "config": { "primary": false } } }
    },
    "tft": {
        "module": "tft_with_touch",
        "on": { "spi.spi2": {} },
        "devices": {
            "lcd": { "on": { "spi.spi2": { "cs": 5 } }, "pins": { "dc": 2, "rst": 4 } },
            "touch": { "on": { "spi.spi2": { "cs": 16 } }, "pins": { "int": 17 } }
        }
    }
}
```

`on` говорит, к какой шине присоединяется каждый вид шины модуля. `pins` и `config` рядом — для модуля из
одной части; модуль из нескольких частей получает подключение по частям, в `devices`, и так же меняется одна
часть, как 2004 выше, который рядом с другим дисплеем не основной. Часть называется на плате
`<использование>_<часть>`, `text_lcd`, сколько бы частей ни было у модуля, и то, что части говорят друг о
друге (`over`, `after`), следует новым именам. Модуль — это плата, использованная как часть другой, с теми
же полями, и у него может быть свой чип: C6 на SDIO у P4 — это модуль с `mcu`.

## Символьный дисплей

```c
board_character_display_t lcd;
if (board_character_display_init(&lcd)) {
    lcd_set_cursor(board_hd44780(&lcd), 0, 0);
    lcd_write_str(board_hd44780(&lcd), "hello");
}
```

`lcd_write_str` пишет дальше по памяти HD44780, где строка 0 у 20x4 переходит в строку 2, поэтому текст
длиннее строки пишется по строкам, с `lcd_set_cursor` для каждой.

Дисплей поднимается очищенным, с включённой подсветкой; `lcd.cols` и `lcd.rows` — его размеры. Остальное —
API hd44780 (`hd44780.h`), которое приносит правило манифеста, когда у платы есть такой дисплей. Он
использует I2C-мастер платы, общий с её сенсорной панелью и кодеком; адрес переходника записан в данных
модуля (`0x27`; переходник с иначе запаянными перемычками адреса требует изменить данные). На плате без него
`board_character_display_init` возвращает `false`: одна и та же программа работает и с LCD, и без него.

## Как описан модуль

2004 из примера, `components/local-boards/modules/lcd2004_pcf8574/module.json`, не имеет ни чипа, ни шин.
Его `on` называет только вид шины: подключение — дело платы.

```json
{
    "format": "jef-sure/boards", "format_version": 2, "kind": "module",
    "name": "lcd2004_pcf8574",
    "title": "2004 LCD on a PCF8574",
    "description": "...",
    "power": [{ "name": "VCC", "source": "connector", "volts": [4.5, 5.5], "feeds": ["lcd"] }],
    "devices": {
        "lcd": { "chip": "hd44780", "on": { "i2c": { "address": "0x27" } }, "logic": "VCC", "config": { "primary": true, "geometry": "20x4" } }
    }
}
```

Клей платы определяет для него `board_character_display_init`. В `src/board_display_none.c` эта функция тоже
есть и возвращает `false`, но под `#if !CONFIG_BOARD_DISPLAY_HD44780`, так что на плате с таким дисплеем
компонуется функция клея.

## Каталог и программа

Модули `catalog/modules/` — изделия, которые страница предлагает в комплектах. Собственный модуль программы,
как часть, которую её автор собрал из деталей, лежит в `components/local-boards/modules/` программы, в
раскладке `catalog/`, как 2004 из примера. Клей запускает дисплеи, сенсорные панели, звук и кнопки; модуль
другого рода (датчик, радио) — это данные: комплект называет библиотеку его чипа, а программа его запускает.
