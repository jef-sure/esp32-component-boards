# Формат данных: board.json

Один файл на плату, `boards-data/<board>/board.json`. Формат `jef-sure/boards`,
`format_version` 1. Всё, что читает генератор, находится здесь; редактор в
`editor/index.html` редактирует тот же файл, проверяя эти правила по мере ввода.

## Плата

```json
{
    "format": "jef-sure/boards",
    "format_version": 1,
    "name": "jc1060p470",
    "title": "Guition JC1060P470",
    "description": "7-inch 1024x600 JD9165 on MIPI-DSI, GT911 touch, ES8311 sound",
    "mcu": { "target": "esp32p4", "flash_mb": 16, "psram_mb": 32, "notes": "..." },
    "buses": { ... },
    "display": { ... },
    "touch": { ... },
    "sound": { ... },
    "button": { ... },
    "sd": { ... }
}
```

| поле | значение |
|---|---|
| `name` | имя каталога; строчные латинские буквы, цифры и `_`. Становится `CONFIG_BOARD_SELECT_<NAME>` и именем файла клея |
| `title` | что показывают меню и `board_info()->title` |
| `description` | одно предложение; подсказка в меню и заголовочный комментарий клея |
| `mcu.target` | `esp32`, `esp32s3` или `esp32p4` (чипы, для которых в генераторе есть таблица хостов SPI) |
| `mcu.flash_mb`, `mcu.psram_mb` | для людей; настройки несёт `sdkconfig.defaults` |
| `mcu.notes` | что кодирует `sdkconfig.defaults` и почему: ревизия чипа, скорость PSRAM |
| `module` | `true` для устройства, которое едет на шине другой платы; тогда ни `mcu`, ни `buses`, ни `button`, а дисплей — символьный |
| `extra_requires` | компоненты ESP-IDF, которые нужны клею при компоновке сверх того, что следует из структуры; нужно редко |

## Шины

`buses` — словарь родов, каждый род — словарь именованных шин. Имя шины — это
заявка на хост или порт чипа: `spi.spi2` — SPI2 чипа, `i2c.i2c0` — его I2C0,
`i2s.i2s0` — его I2S0. Устройство ссылается на шину как `"<kind>.<name>"`.

```json
"buses": {
    "spi":  { "spi2": { "hz": 40000000, "mosi": 13, "miso": 12, "sclk": 14 },
              "spi3": { "hz": 1000000, "mosi": 32, "miso": 39, "sclk": 25 } },
    "qspi": { "spi2": { "hz": 40000000, "d0": 21, "d1": 48, "d2": 40, "d3": 39, "sclk": 47 } },
    "i2c":  { "i2c0": { "sda": 7, "scl": 8 } },
    "i2s":  { "i2s0": { "mclk": 13, "bclk": 12, "ws": 10, "dout": 9, "din": null } },
    "dsi":  { "dsi0": { "lanes": 2, "lane_mbps": 750, "phy_ldo_chan": 3, "phy_ldo_mv": 2500 } },
    "p8":   { "i80":  { "d0": 0, "...": 0, "d7": 0, "wr": 0, "rd": null, "dc": 0, "hz": 10000000 } },
    "sdio": { "sdio0": { "clk": 18, "cmd": 19, "d0": 14, "d1": 15, "d2": 16, "d3": 17, "reset": 54 } }
}
```

Роды, которые компонент настраивает сам, с полями, которых он требует:

| род | имя | поля |
|---|---|---|
| `spi` | хост: `spi2`, `spi3` | `mosi`, `miso`, `sclk`; `hz` необязательно |
| `qspi` | хост: `spi2`, `spi3` | `d0`..`d3`, `sclk`; `hz` необязательно |
| `i2c` | порт: `i2c0`, `i2c1` | `sda`, `scl` |
| `i2s` | порт: `i2s0`, `i2s1` | `mclk`, `bclk`, `ws`, `dout`; `din` — пин или `null` |
| `dsi` | `dsi0` | `lanes`, `lane_mbps`, `phy_ldo_chan`, `phy_ldo_mv` |
| `p8` | любое | `d0`..`d7`, `wr`, `dc`, `hz`; `rd` — пин или `null` |

Любой другой род (`sdio`, `uart`, `sdspi` у CYD для пинов SD, которым не
осталось хоста) хранится как данные: каждое значение должно быть числом,
строкой или `null`. Программа читает его через
`board_bus_get("sdio.sdio0", "clk", &pin)`. Когда компонент научится
настраивать такой род, тот переедет в таблицу выше и получит клей; данные не
изменятся.

Компонент настраивает только одну шину I2C (первую по имени); её мастер
разделяют тач, кодек и модуль символьного дисплея.

## Дисплей

Пиксельная панель под управлением DGX:

```json
"display": {
    "driver": "ili9341",
    "bus": { "bus": "spi.spi2", "cs": 15, "dc": 2 },
    "panel": { "width": 240, "height": 320, "mm_w": 43, "mm_h": 58 },
    "original_orientation": { "x": "right-left", "y": "top-bottom", "swap": true },
    "rst": null,
    "backlight": 21,
    "backlight_on_high": true,
    "depth_bits": 16
}
```

| поле | значение |
|---|---|
| `driver` | `jd9165`, `jd9365` (MIPI-DSI), `nv3041a` (QSPI), `ili9341` (SPI или i80). Генератор знает, какой заголовок DGX, какие символы `DGX_ENABLE_*` и какие глубины пикселя принимает каждый |
| `bus.bus` | имя из `buses` рода `spi`, `qspi`, `dsi` или `p8` |
| `bus.cs`, `bus.dc` | собственные стробы панели: `cs` и `dc` на SPI, `cs` на QSPI и i80, ни одного на DSI |
| `panel` | стекло **как его сканирует контроллер**: пиксели и миллиметры в одном направлении. Генератор отказывает пикселям и миллиметрам, которые лежат в разные стороны или чьи пропорции расходятся больше чем на пятую часть |
| `original_orientation` | как плата показывает стекло: `x` — `left-right` или `right-left`, `y` — `top-bottom` или `bottom-top`, `swap` истинно, когда x дисплея идёт вдоль столбцов стекла (альбомная ориентация на портретной панели). Клей применяет это при инициализации; `board_display` сообщает размер как лежит, после перестановки |
| `rst`, `backlight` | пины или `null`; `backlight_on_high` говорит, какой уровень зажигает подсветку |
| `depth_bits` | 16 везде, 24 — ещё и на панелях DSI |

Символьный дисплей (hd44780) на плате или как модуль:

```json
"display": {
    "driver": "hd44780",
    "geometry": "20x4",
    "bus": { "bus": "i2c.i2c0", "address": "0x27" }
}
```

`bus.bus` — это `i2c.<name>` с `address` переходника либо `gpio.4bit` /
`gpio.8bit` с `bus.pins`: `rs`, `en`, `d4`..`d7` (и `d0`..`d3` для 8-битного).
Геометрии: `8x2`, `16x2`, `16x4`, `20x2`, `20x4`, `40x2`.

## Тач

```json
"touch": {
    "kind": "gt911",
    "bus": "i2c.i2c0",
    "address_try": ["0x5d", "0x14"],
    "x_max": 1023, "y_max": 599,
    "fingers": 5,
    "rst": null, "int": null,
    "calibration": { ... }
}
```

| род | шина | поля |
|---|---|---|
| `gt911` | `i2c.*` | `address_try` (адреса, пробуемые по порядку; GT911 выбирает один при включении питания), `fingers`, `rst`, `int` |
| `gsl3680` | `i2c.*` | `rst`, `int`, `fingers`; прошивка приходит из программы, см. [touch-firmware.md](touch-firmware.md) |
| `esp_lcd_touch` | `spi.*` | `component` (`namespace/name` в реестре компонентов, с версией в таблице генератора), `header`, `cs`, `irq`, `hz` (по умолчанию 1 МГц), `fingers`, `resistive` |

`x_max` и `y_max` — диапазон сырых координат, которые выдаёт панель.
`calibration` — измеренная калибровка DGX-DI, см.
[calibration.md](calibration.md); `"measured": false` внутри неё помечает
заглушку, и клей предупреждает при старте.

Тач рода `esp_lcd_touch` на собственной шине (не шине дисплея) получает
инициализацию своего хоста SPI от клея; на шине дисплея это уже сделал DGX.

## Звук

```json
"sound": { "kind": "es8311", "bus": "i2c.i2c0", "address": "0x18", "i2s_bus": "i2s.i2s0",
           "pa": 11, "pa_voltage": 5.0, "codec_dac_voltage": 3.3, "sample_rate": 22050, "volume": 25 }
```

```json
"sound": { "kind": "dac", "out": 26, "pa": null, "sample_rate": 22050 }
```

`es8311`: кодек на шине I2C (`bus`, `address`), передающий поток по шине I2S
(`i2s_bus`), пин включения его усилителя `pa` (или `null`), напряжения,
которые esp_codec_dev хочет знать для своего усиления, `volume` кодека
(0..100). `dac`: собственный ЦАП ESP32 на GPIO 25 или 26, питаемый DMA с
частотой `sample_rate`; `pa` — пин или `null`. В обоих случаях 16-битные
моно-сэмплы.

## Кнопка, слот SD

```json
"button": { "pin": 35, "active_low": true },
"sd": { "bus": "spi.spi3", "cs": 5 }
```

Слот — устройство на обычной шине SPI платы, с собственным `cs`. Когда для
него не осталось хоста (CYD: на SPI2 дисплей, на SPI3 тач), его пины уходят в
`buses` под род, который компонент не настраивает, как данные.

## Чему генератор отказывает

Помимо форм выше: имя шины, для которой у чипа нет хоста; устройство на шине,
которую плата не разводит; тач без дисплея; звук `dac` на чипе, отличном от
ESP32; модуль с собственным чипом, шинами или кнопкой; GPIO, которого у чипа
нет; выход на GPIO только для ввода (34..39 на ESP32); два владельца одного
GPIO. `tools/board_pins.py <board>` показывает карту, по которой делаются
последние проверки.
