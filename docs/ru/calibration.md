# Калибровка

Две вещи на плате измеряются, а не считываются со схемы, и компонент хранит их
вместе с платой: калибровка её тач-панели и настройка шины MIPI-DSI.

## Калибровка тача

Тач-панель сообщает сырые координаты в собственном диапазоне (`x_max`, `y_max`
в данных). DGX-DI отображает их на дисплей калибровкой, измеренной на
настоящей плате: аффинное преобразование плюс три корректирующих узла на
каждую ось, и тайминги того, как палец появляется и уходит (`down_ms`,
`up_ms`, `blink_ms`).

В `config.calibrations` тача хранится то, что измерили, а не само преобразование: это список, одна
запись на измерение, новейшая последняя. В записи лежат точки, в которые целились, каждая названа
по своему месту на дисплее в его собственной ориентации: `left_up`, `right_up`, `left_down`,
`right_down`, а если их мерили, ещё `up`, `down`, `left`, `right`, `middle`. У точки два поля:
`meant` — пиксель, в который целились, `device` — что там вернул контроллер тача. Углы обязательны:
TFT_eSPI и LovyanGFX калибруются по четырём углам. Они целятся в сами углы, а DGX-DI ближе к
середине, поэтому при экспорте точки надо продолжить до углов. Экспорта пока нет.

`x_max`, `y_max`, `width` и `height` говорят, с чем измеряли. В `libraries` лежит то, чем
пользуется только одна библиотека. У DGX-DI это `blink_ms` и `gap_ms`, как вела себя панель, а
также `rounds` и числа `*_tenths`, как прошло измерение.

`board_touch_start` строит калибровку DGX-DI из точек через `dgx_di_calibration_make()`, а её
тайминги через `dgx_di_calibration_steady()`. Самого преобразования в данных нет, поэтому
разойтись с точками оно не может.

`measured_with` говорит, с какими версиями измерено: изменение в библиотеке может сделать
калибровку неверной. `rule` словами говорит, когда запись годится, `notes` — что ещё известно.
Инструменты `rule` пока не читают: клей берёт последнюю запись.

Калибровка измеряется на **одной** плате данного рода. Другая плата того же
рода близка, но не идентична; если это важно, измерьте заново. Калибровка
действительна для того размера дисплея и диапазона панели, с которыми её
измеряли: указатель отказывается от несовпадающей, и лог говорит *the
calibration is not this board's*.

### Измерение

DGX-DI предоставляет `dgx_di_calibrate_measure(device, screen, rounds, &calibration)`
(`dgx_di_calibrate.h`): на дисплее по очереди мигают мишени, на каждую
опускается палец, и после всех раундов функция заполняет калибровку и пишет её
в лог и словами, и как C-инициализатор. Пример `touch_check` из DGX-DI
запускает её на собственном дисплее платы. В программе этого компонента:

```c
struct board_display display = {0};
struct board_touch touch;
board_display_init(&display);
board_touch_start(&display, &touch);
dgx_di_calibration_t measured;
if (dgx_di_calibrate_measure(board_dgx_di_device(&touch), board_dgx_screen(&display), 3, &measured)) {
    char text[1024];
    dgx_di_calibration_code(&measured, text, sizeof text);  /* the C initializer, printed to the log */
    puts(text);
}
```

Дайте задаче, которая её запускает, достаточно стека (ей нужно около 3 КБ) и
пусть ничто другое тем временем не рисует.

### Сохранение

Сохраните лог и отдайте его инструменту: он запишет числа в данные платы и уберёт
`measured`: `python3 tools/board_calibration.py <board> < log.txt`. Затем запустите
`tools/boards_gen.py --all` и соберите.
`off_tenths` и `left_tenths` в записи говорят, насколько касания отклонялись без калибровки и с ней,
в десятых долях пикселя, по данным измерения.

Инструмент берёт каждую точку из касаний в логе, как их медиану. Калибровка, построенная из них при
старте, совпадает с той, что напечатал лог: на CYD S028R сходятся все числа. Если дать только
инициализатор на C, точки будут пересчитаны из него: это места, куда калибровка поставила цели.
Так сделаны точки JC1060P470C, JC4827W543C и JC8012P4A1C, потому что их логи не сохранились, и их
калибровки отличаются от исходных записей не больше чем на 2 пикселя.

Девять точек стоят того, чтобы их мерить: одни углы теряют изгиб. На JC8012P4A1C калибровка по углам
расходится с калибровкой по девяти точкам до 13 пикселей.

Плата, калибровку которой никогда не измеряли, имеет `"measured": false`:
клей предупреждает при старте, и таблица README об этом говорит.

## Настройка DSI

На MIPI-DSI шина DGX решает, что идёт через 2D DMA чипа, а что через
процессор, и сколько запаса оставлять перед развёрткой панели, по числам,
которые зависят от чипа, его PSRAM и панели. Шина начинает с чисел той платы,
на которой писался DGX; `dgx_dsi_bench()` измеряет плату под рукой за доли
секунды, `dgx_dsi_tune()` отдаёт результат шине. Компонент открывает шину как
`board_display.bus` именно для этого. Программа измеряет один раз и хранит
числа в NVS:

```c
#include "bus/dgx_dsi_esp32.h"
if (display.bus && display.bus->bus_type == DGX_BUS_DSI) {
    dgx_dsi_tuning_t tuning;
    /* read it from NVS; if there is none or dgx_dsi_tune() refuses it: */
    if (dgx_dsi_bench(display.bus, &tuning) && dgx_dsi_tune(display.bus, &tuning)) { /* write it to NVS */ }
}
```

В отличие от калибровки тача, это пока не хранится в данных платы: оно
принадлежит конкретному чипу не меньше, чем плате. Будущая версия будет
хранить измеренные калибровки обоих родов в `catalog/boards/<board>/calibrations/`
и позволит программе выбирать по ревизии чипа.
