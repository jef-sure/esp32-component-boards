# Инструменты

Все в `tools/`, Python 3.8 или новее, никаких пакетов сверх стандартной
библиотеки. Запускайте их из корня репозитория (или из
`managed_components/jef-sure__boards/`).

## boards_gen.py

```sh
python3 tools/boards_gen.py --all          # everything, from every board and module
python3 tools/boards_gen.py cyd_s028r      # one board's glue and board.cmake only
```

Читает `catalog/boards/*/board.json` и `catalog/modules/*/module.json`, накладывает
каталог, применяет `catalog/rules.json`, отказывается от того, для чего не может
сделать клей (см. [data-format.md](data-format.md)), и записывает:

- `boards/<board>/<board>.c` и `board.cmake` для каждой платы и модуля;
- `boards/boards.cmake`: списки, по которым компилирует `CMakeLists.txt` компонента;
- `Kconfig`: choice, опции модулей, скрытые символы;
- `dependencies:` в `idf_component.yml`, между `# boards: dependencies
  generated` и `# boards: end of generated`;
- таблицу плат в `README.md` и `README.ru.md`, между
  `<!-- boards:table -->` и `<!-- boards:end -->`.

Он записывает файл только когда его содержимое меняется. Таблицы в его начале
— это знание, которое у него есть сверх данных: какой заголовок DGX и какие
символы `DGX_ENABLE_*` принимает драйвер панели, какие глубины пикселя, какие
роды тача, какой компонент реестра и какую версию приносит каждая возможность.

## check_boards.py

```sh
python3 tools/check_boards.py                 # the data and the generated agree
python3 tools/check_boards.py --host-syntax   # and every glue and the core compile against test/fake
python3 tools/check_boards.py --fix           # write what differs instead of complaining
```

Код возврата 1 и по строке на каждую находку в stderr, когда: `board.json` не
читается; сгенерированный файл расходится с тем, что говорят данные, или
отсутствует; `sdkconfig.defaults` платы отсутствует или не выбирает её чип и
её саму; `sdkconfig.defaults` модуля не включает его; клей не определяет
каждую функцию `boards.h`; два владельца делят один GPIO или выход управляет
GPIO только для ввода; у компонента, который называют данные, нет правила
манифеста; правило называет символ, которого нет в Kconfig. CI запускает его
первым.

`--host-syntax` компилирует каждый клей и исходники `src/` и `adapters/` хостовым `gcc -std=gnu11
-fsyntax-only -Wall -Wextra -Werror` против `test/fake/` — заголовков-заглушек,
повторяющих форму настоящих объявлений ESP-IDF, DGX, DGX-DI и hd44780. Когда
настоящий заголовок меняет форму, генератор и заглушки меняются вместе.
Секунды, без ESP-IDF; настоящей проверкой остаётся сборка в CI.

## board_pins.py

```sh
python3 tools/board_pins.py cyd_s028r           # GPIO -> owner, conflicts marked
python3 tools/board_pins.py cyd_s028r --tree    # chip -> buses -> devices -> pins
python3 tools/board_pins.py --all               # every board's conflicts, for CI
```

Карта, по которой делаются проверки, — чтобы на неё смотрел человек: каждый
GPIO, который называют данные, кто им владеет и в каком направлении, с
пометками *TWO OWNERS*, *INPUT ONLY, DRIVEN* и *NOT A GPIO OF THIS CHIP* рядом
с нарушителями.

## board_select.py

```sh
python3 tools/board_select.py cyd_s028r ~/myproject
python3 tools/board_select.py jc1060p470c --module lcd2004_pcf8574 --reset ~/myproject
```

Записывает `~/myproject/sdkconfig.defaults.board`: умолчания платы, затем
каждого модуля. С `--reset` переносит существующий `sdkconfig` в
`sdkconfig.old`, чтобы новые умолчания были прочитаны. См.
[choosing-a-board.md](choosing-a-board.md).

## board_bom.py

```sh
python3 tools/board_bom.py my_board --project .                        # одно изделие
python3 tools/board_bom.py my_board --project . --units 10 --shop AliExpress  # десять, по ценам одного магазина
python3 tools/board_bom.py my_board --project . --units 10 --duty 3 EUR  # со сбором на тарифный код
python3 tools/board_bom.py my_board --project . --csv my_board.csv      # строки для таблицы
```

Строка — это то, что покупается целиком: базовая плата проекта, затем модули и устройства,
которые проект добавил, одинаковые товары в одну строку. Чипы купленной платы в строки не
идут, а плата с `extends` — это вариант, одна покупка. Поэтому изделие записывается как
`kind: project` над базовой платой.

Цены — диапазоны, поэтому итог тоже диапазон. Строка без цены называется по имени, а итог тогда
читается как «не меньше». Валюты не пересчитываются. Для заданного количества берётся по каждому
магазину предложение с наибольшим `qty`, до которого количество дотягивает.

Доставка и пошлина зависят от заказа, поэтому в данных их нет. `--duty` добавляет сумму на
тарифный код: наименьшее число кодов — известные коды в одной посылке, наибольшее — каждая строка
в своей посылке. Когда сбор действует, инструмент не знает. В ЕС с 1 июля 2026 это
[3 евро на тарифную классификацию для товаров до 150 евро](https://commission.europa.eu/news-and-media/news/ensuring-fairness-and-safety-eur3-customs-duty-low-value-parcels-2026-06-29_en),
так что более крупный заказ в эту сумму не укладывается. Доставка не считается вовсе.

## check_format.py

```sh
python3 tools/check_format.py
```

Нужны `jsonschema` и `node`; первый есть в Python из ESP-IDF. Проверяет каждый файл
`catalog/` и `test/format/catalog/` по `catalog/format.schema.json`, каждую плату через
слияние и правила, случаи `test/format/good/` и `test/format/bad/`, а также что
`tools/rules.py` и `editor/rules.js` находят одно и то же, а `tools/resolve.py` и
`editor/resolve.js` дают одно и то же для каждого документа, прошедшего схему.

## board_pins.py и свободные пины

```sh
python3 tools/board_pins.py jc1060p470c --free        # что осталось для подключаемого
python3 tools/board_pins.py jc1060p470c --free ADC    # то же, что умеет это
python3 tools/board_pins.py jc1060p470c --json        # каждый GPIO, для инструментов
```

Что умеет GPIO, берётся из таблицы чипа в документации ESP-IDF и хранится в `catalog/mcu/` скриптом
`tools/make_mcu.py`: аналоговые функции, бутстрап, примечания. Кто его занял, берётся из платы,
включая линии устройств. Пины на разъёмах идут первыми. Линия, которой намеренно пользуются
несколько устройств, говорит, когда она свободна.

## make_mcu.py

```sh
python3 tools/make_mcu.py [каталог ESP-IDF]
```

Записывает `catalog/mcu/` из `soc_caps.h` ESP-IDF.

## update_rates.py

Пишет `catalog/rates.json` из справочных курсов Европейского центрального банка, чтобы цены в любой валюте
сравнивались на странице. Нужна только сеть; страница лишь читает готовый файл.

## sync_versions.py

```sh
python3 tools/sync_versions.py
```

Заполняет `versions` в записях библиотек `esp-idf`: из реестра компонентов — с чем собирается и что требует каждая версия, из тегов git — версии, которых в реестре нет.
Версия, которой в реестре ещё нет, остаётся как записана.

## Страница

`editor/index.html` отвечает, что собрать и на чём, и правит файлы каталога. Ей не нужны ни сборка, ни
сеть, только статический сервер из корня репозитория: Live Server из VS Code или

```sh
python3 -m http.server 8000
```

Откройте на этом сервере `/editor/`: каталог загрузится сам.

### select

Форма строится из `catalog/questions.json`. Каждая плата каталога сразу получает ответ: что на ней
есть, каких модулей не хватает и как их подключить, цена и то, чего нет в данных, с пометкой `?`.
Неподходящие платы показаны с причиной. Решатель только предлагает: каждый комплект — это проект, и
решают проверки инструментов. Поэтому два PN532 сами уходят на SPI: правила не пускают один адрес
I2C дважды.

Решатель подключает I2C, SPI, QSPI и UART и линии, которые нужны чипу помимо шины, например BUSY и
RST у PN5180. Модуль на DSI занимает свободную шину DSI платы шлейфом, а его тайминги остаются
неизвестной комплекта: их меряют на плате. Решатель берёт свободные пины, которые выходят на разъём,
и не трогает пины начальной конфигурации, флеша и консоли. К шине платы он подключается, только если
её линии выходят наружу и её не держит дисплей, и эти линии тоже показывает. Для каждого модуля он
выбирает самую низкую подходящую линию питания из выходящих наружу и просит преобразователь уровней,
если линии модуля поднимаются выше того, что выдерживают ножки чипа, см.
[Питание и уровни](data-format.md#питание-и-уровни). Токи он не суммирует.

Тон и PWM — это выходы чипа: у каждого своя частота, у тона допуск и джиттер, у PWM разрядность скважности, и
любой может меняться на ходу. Решатель перебирает источники чипа в порядке `frequency_sources`, считает для
каждого достигнутую частоту и берёт первый подходящий: обычно LEDC, затем MCPWM и RMT, кварц платы через CLK_OUT,
I2S с APLL. Частота принадлежит таймеру, поэтому выходы с одной настройкой делят таймер. Цифры расчётные, не
измеренные.

Комплекты идут в таком порядке: подходящие, меньше неизвестных, меньше модулей, меньше проводов,
затем цена. Бюджет делает цену критерием: тогда она идёт сразу за неизвестными, а отсутствие цены
считается неизвестным. `tools/check_format.py` отдаёт комплекты из `test/solver/` ещё и генератору.

`make a project…` спрашивает папку, и от неё зависит, что произойдёт:

- пустая папка или папка, где есть только `.git`, README, лицензия и `.gitignore`, получает весь
  проект. То, что там уже лежит, остаётся;
- папка с `CMakeLists.txt` считается программой и получает только свою плату в
  `components/local-boards/`;
- любая другая папка отвергается.

Сначала показывается список того, что произойдёт, и до кнопки `write` ничего не пишется. Файл платы,
который отличается, заменяется только по галочке, и ничего никогда не удаляется. Если после списка
какой-то файл изменился, не пишется ничего. Комплекту без модулей
файл платы не нужен: проект называет плату каталога. Страница не связывается с GitHub: результат
— папка, а дальше git или ничего.

Плата выбирается до первой сборки, потому что зависимости определяются тем, что на ней есть:
`board_select.py`, затем `idf.py build`. В проекте, собранном для другой платы, нужен
`idf.py reconfigure build`; `board_select.py` об этом скажет.

### edit

`open a folder` принимает программу или её `components/local-boards`, чтобы править платы этой программы. Принимает и папку репозитория:
тогда Chromium сохраняет прямо в каталог. Страницу, открытую из файла, некому обслужить, поэтому там
сначала нужен репозиторий.

Слева список документов каталога, рядом дерево открытого. `card` показывает поля узла и то, что
схема говорит о каждом: написанное в файле обычным текстом, унаследованное серым. Значение,
введённое поверх унаследованного, попадает в этот файл. В файле с `extends` крестик на
унаследованном поле пишет `null`: поле убирается здесь, а база остаётся как есть. `pins` — карта
GPIO, `json` — файл в том виде, как он сохранится, и собранная плата, как её читают инструменты.

Каждое изменение проходит те же проверки, что и в инструментах: схему, загрузчик, правила и карту
пинов. Проблемы перечислены над карточкой. Chromium сохраняет в открытую папку; без неё или в другом
браузере страница отдаёт файл, и его надо положить на место руками. Затем запустите
`tools/boards_gen.py --all`, а для платы программы `tools/board_select.py`.

Платы программы показаны отдельно, поверх каталога, и новое попадает туда. Без программы новый
документ попадает в каталог, поэтому `project` не предлагается.

Файлы `catalog/mcu/` пишет `tools/make_mcu.py`, поэтому здесь они только для чтения. Так же и часть
модуля на плате: её правят в модуле или через `modules` платы.

`tools/check_format.py` сверяет `editor/schema.js`, `editor/pins.js` и JSON, который сохраняет
страница, с инструментами на Python: на всех документах и на их испорченных копиях.

## test/fake

Заголовки-заглушки для `--host-syntax`. Не входят в пакет реестра. Новому
include в сгенерированном клее нужна заглушка здесь с тем же именем и формой
того, что клей вызывает.

## Workflow CI

`.github/workflows/build.yml`: `check_boards.py --host-syntax` и
`board_pins.py --all`, затем `examples/hello_board` для каждой платы и
`examples/hello_lvgl` для каждой платы с графическим дисплеем под двумя
версиями ESP-IDF, плюс одна сборка
`hello_board` с модулем 2004, каждая в своём job. Добавляйте плату в матрицу, когда добавляете её в данные.
