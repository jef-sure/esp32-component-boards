# Инструменты

Все в `tools/`, Python 3.8 или новее. Большинству хватает стандартной
библиотеки: `check_format.py` нужны `jsonschema` и Node.js, на котором идёт
JavaScript страницы; импортёрам нужен `jsonschema`, а `import_pictures.py` —
Chrome и ImageMagick. Запускайте их из корня репозитория (или из
`managed_components/jef-sure__boards/`).

Пакет реестра несёт инструменты, которыми пользуется программа: `board_select.py`, `board_project.py`,
`board_pins.py`, `board_bom.py`, `board_calibration.py`, `boards_mcp.py`, а также `boards_gen.py`, `resolve.py` и
`rules.py`, которые они импортируют. Проверки, импортёры, `audit.py`, `make_mcu.py`, `update_rates.py`,
`take_report.py` и `sync_versions.py` — для репозитория: им нужны `test/`, ESP-IDF или сеть.

## boards_gen.py

```sh
python3 tools/boards_gen.py --all          # everything, from every board and module
python3 tools/boards_gen.py cyd_s028r      # one board's glue and board.cmake only
```

Читает `catalog/boards/*/board.json` и `catalog/modules/*/module.json`, накладывает
каталог, применяет `catalog/rules.json`, отказывается от того, для чего не может
сделать клей (см. [data-format.md](data-format.md)), и записывает:

- `boards/<board>/<board>.c` и `board.cmake` для каждой платы и модуля, `display.cmake`
  для каждой платы;
- `boards/boards.cmake`: списки, по которым компилирует `CMakeLists.txt` компонента;
- `Kconfig`: choice, опции модулей, скрытые символы;
- `dependencies:` в `idf_component.yml`, между `# boards: dependencies
  generated` и `# boards: end of generated`;
- таблицу плат в `README.md` и `README.ru.md`, между
  `<!-- boards:table -->` и `<!-- boards:end -->`.

Он записывает файл только когда его содержимое меняется. Таблицы в его начале
— это знание, которое у него есть сверх данных: какой заголовок DGX и какие
символы `DGX_ENABLE_*` принимает драйвер панели, какие глубины пикселя, какие
роды тача, какой компонент реестра и какую версию приносит каждая возможность.

## check_boards.py

```sh
python3 tools/check_boards.py                 # the data and the generated agree
python3 tools/check_boards.py --host-syntax   # and every glue and the core compile against test/fake
python3 tools/check_boards.py --fix           # write what differs instead of complaining
```

Код возврата 1 и по строке на каждую находку в stderr, когда: `board.json` не
читается; сгенерированный файл расходится с тем, что говорят данные, или
отсутствует; `sdkconfig.defaults` платы отсутствует или не выбирает её чип и
её саму; `sdkconfig.defaults` модуля не включает его; клей не определяет
каждую функцию `boards.h`; два владельца делят один GPIO или выход управляет
GPIO только для ввода; у компонента, который называют данные, нет правила
манифеста; правило называет символ, которого нет в Kconfig. CI запускает его
первым.

`--host-syntax` компилирует каждый клей и исходники `src/` и `adapters/` хостовым `gcc -std=gnu11
-fsyntax-only -Wall -Wextra -Werror` против `test/fake/` — заголовков-заглушек,
повторяющих форму настоящих объявлений ESP-IDF, DGX, DGX-DI и hd44780. Когда
настоящий заголовок меняет форму, генератор и заглушки меняются вместе.
Секунды, без ESP-IDF; настоящей проверкой остаётся сборка в CI.

## board_pins.py

```sh
python3 tools/board_pins.py cyd_s028r           # GPIO -> owner, conflicts marked
python3 tools/board_pins.py cyd_s028r --tree    # chip -> buses -> devices -> pins
python3 tools/board_pins.py --all               # every board's conflicts, for CI
python3 tools/board_pins.py jc1060p470c --display  # 1024x600 154x86: pixels and mm, as shown
```

`--display` печатает то же, что содержат `BOARD_PIXELS` и `BOARD_MM`, для Makefile без
CMake, например для сборки игры на компьютере: `HOST_DISPLAY := $(shell python3
.../board_pins.py jc1060p470c --display)`. Плата без пиксельного дисплея ничего не
печатает и выходит с кодом 1.

Карта, по которой делаются проверки, — чтобы на неё смотрел человек: каждый
GPIO, который называют данные, кто им владеет и в каком направлении, с
пометками *TWO OWNERS*, *INPUT ONLY, DRIVEN* и *NOT A GPIO OF THIS CHIP* рядом
с нарушителями.

## board_select.py

```sh
python3 tools/board_select.py cyd_s028r ~/myproject
python3 tools/board_select.py jc1060p470c --module lcd2004_pcf8574 --reset ~/myproject
python3 tools/board_select.py host --as jc8012p4a1c ~/myproject    # the computer, as large as the 10-inch board
```

Записывает `~/myproject/sdkconfig.defaults.board`: умолчания платы, затем
каждого модуля. С `--reset` переносит существующий `sdkconfig` в
`sdkconfig.old`, чтобы новые умолчания были прочитаны. См.
[choosing-a-board.md](choosing-a-board.md).

Каждый записанный файл начинается с команды, которой он сделан, и с версии и коммита компонента. Когда компонент
меняется, `board_select.py --again ~/myproject` делает все такие файлы проекта заново той же командой; `sdkconfig`,
сделанный раньше, хранит то, что в нём было, поэтому изменения берёт `--reset`.

## board_project.py

```sh
python3 tools/board_project.py ~/my_game --board jc8012p4a1c
python3 tools/board_project.py ~/terminal --board jc1060p470c --module lcd2004_pcf8574
python3 tools/board_project.py ~/again --selection ~/old/selection.json
```

Новый проект на плате, выбранной вручную, без страницы: те же файлы, что страница пишет в новую папку (их
перечисляет `editor/skeleton/files.json`, оба читают этот список), заполненные так же, и `selection.json` без
ответов. Компонент берётся из git на коммите этой копии. `--selection` берёт плату и модули из `selection.json`.
Папка пуста или содержит только `.git`, `.gitignore`, README или LICENSE; ничего в ней не заменяется. Следующая
команда, которую он печатает, — та же, что в README проекта.

## board_bom.py

```sh
python3 tools/board_bom.py my_board --project .                        # одно изделие
python3 tools/board_bom.py my_board --project . --units 10 --shop aliexpress  # десять, по ценам одного магазина
python3 tools/board_bom.py my_board --project . --units 10 --duty 3 EUR  # со сбором на тарифный код
python3 tools/board_bom.py my_board --project . --csv my_board.csv      # строки для таблицы
```

Строка — это то, что покупается целиком: базовая плата проекта, затем модули и устройства,
которые проект добавил, одинаковые товары в одну строку. Чипы купленной платы в строки не
идут, а плата с `extends` — это вариант, одна покупка. Поэтому изделие записывается как
`kind: project` над базовой платой.

Цены — диапазоны, поэтому итог тоже диапазон. Строка без цены называется по имени, а итог тогда
читается как «не меньше». Валюты не пересчитываются. Для заданного количества по каждому магазину берутся
предложения с наибольшим `qty`, до которого количество дотягивает, а из нескольких — их медиана, как на странице;
строка, которая продаётся только упаковкой, покупается упаковкой. `--shop` находит магазин из
`catalog/shops.json` по ключу, названию или адресу, так же как отчёт.

Доставка и пошлина зависят от заказа, поэтому в данных их нет. `--duty` добавляет сумму на
тарифный код: наименьшее число кодов — известные коды в одной посылке, наибольшее — каждая строка
в своей посылке. Когда сбор действует, инструмент не знает. В ЕС с 1 июля 2026 это
[3 евро на тарифную классификацию для товаров до 150 евро](https://commission.europa.eu/news-and-media/news/ensuring-fairness-and-safety-eur3-customs-duty-low-value-parcels-2026-06-29_en),
так что более крупный заказ в эту сумму не укладывается. Доставка не считается вовсе.

## check_format.py

```sh
python3 tools/check_format.py
```

Нужны `jsonschema` и `node`; первый есть в Python из ESP-IDF. Проверяет каждый файл
`catalog/` и `test/format/catalog/` по `catalog/format.schema.json`, каждую плату через
слияние и правила, случаи `test/format/good/` и `test/format/bad/`, а также что
`tools/rules.py` и `editor/rules.js` находят одно и то же, а `tools/resolve.py` и
`editor/resolve.js` дают одно и то же для каждого документа, прошедшего схему. Считает изделия цепочки в списке
товаров и там, где есть compote из ESP-IDF и git, упаковывает компонент, как это сделал бы реестр, и находит в
архиве только файлы, которые отслеживает git, ни одного из `test/`, `.github/` или `imported/`.

## board_pins.py и свободные пины

```sh
python3 tools/board_pins.py jc1060p470c --free        # что осталось для подключаемого
python3 tools/board_pins.py jc1060p470c --free ADC    # то же, что умеет это
python3 tools/board_pins.py jc1060p470c --json        # каждый GPIO, для инструментов
```

Что умеет GPIO, берётся из таблицы чипа в документации ESP-IDF и хранится в `catalog/mcu/` скриптом
`tools/make_mcu.py`: аналоговые функции, бутстрап, примечания. Кто его занял, берётся из платы,
включая линии устройств. Пины на разъёмах идут первыми. Линия, которой намеренно пользуются
несколько устройств, говорит, когда она свободна.

## make_mcu.py

```sh
python3 tools/make_mcu.py [каталог ESP-IDF]
```

Записывает `catalog/mcu/` из ESP-IDF: `soc_caps.h`, таблицы GPIO из его документации, дерево тактов и
низкоуровневые заголовки LEDC, MCPWM, RMT и I2S. Режимы загрузки по strapping-пинам берутся из даташитов Espressif.

## update_rates.py

Пишет `catalog/rates.json` из справочных курсов Европейского центрального банка, чтобы цены в любой валюте
сравнивались на странице. Нужна только сеть; страница лишь читает готовый файл.

## take_report.py

Берёт цену из issue по форме `price.yml` и добавляет её предложением в файл позиции. Текст issue может написать кто
угодно, поэтому он читается только как поля, а `.github/workflows/reports.yml` передаёт его через файл. Действие
открывает pull request, сливает его человек. На отказ действие отвечает комментарием с причиной, а исправленный текст
issue читается заново. Цена читается так, как её пишут в разных странах: 3.76, 3,76, 1,234.56, 1.234,56, 1 234,56,
1'234.56, 12,34,567, со знаком или кодом своей валюты или без него. Один знак перед тремя цифрами, как в 1,200, читается
двояко, и такая цена отклоняется с обоими прочтениями. Магазин ищется в `catalog/shops.json` по адресу
(`https://de.aliexpress.com/item/...` даёт `aliexpress`), по имени или по близкому имени (`aliexpres`); имя двух
магазинов, как `amazon`, отклоняется. Адрес или имя, которых в списке нет, дают новый магазин без названия, и pull
request просит его написать: до тех пор `check_format.py` магазин не принимает. Продавец принимается только на
площадке или в объявлениях. `check_format.py` проверяет инструмент
на хороших и плохих отчётах.

## import_board_manager.py

Переносит платы из пакетов esp_board_manager в `imported/`, дерево в раскладке `catalog/`, которое инструменты читают
после него. Пакет это данные из сети: он распаковывается отдельно и только читается.

```sh
python3 tools/import_board_manager.py esp_boards=PATH guition_boards=PATH --date 2026-11-01
```

Инструмент не подставляет значений, которых нет в пакете, не берёт тайминги DSI и команды инициализации, не пишет
`shared_pins`. То, что формат отвергает, попадает в `imported/report.json` с причиной, туда же идут пины плат из
каталога в сравнении с пакетами и то, для чего в формате нет места. `check_format.py` проверяет результат и эти правила.

## import_fritzing.py

Переносит модули из деталей Fritzing в `imported/modules/`. Запускается после `import_board_manager.py`, который
переписывает `imported/devices/`.

```sh
python3 tools/import_fritzing.py adafruit=PATH fritzing=PATH --ref adafruit=COMMIT --date 2026-11-01
```

Берутся только факты: контакты, питание по их именам, номер детали. Модулю нужна шина, которую видно по контактам.
Роли идут из слов `catalog/roles.json` и из разделов магазина, если `--shop` указывает на копию его списка; она же даёт цену и убирает то, что больше не продаётся.

## import_pictures.py

Даёт импортированным модулям картинку: рисунок макетной платы их детали Fritzing, который Chrome рисует в квадрат 320 px; он
лежит рядом с модулем как `drawing.webp`. Запускается после `import_fritzing.py` с теми же источниками. Нужны Chrome и ImageMagick.

```sh
python3 tools/import_pictures.py adafruit=PATH fritzing=PATH
```

Рисунки под CC BY-SA 3.0, а значит, и картинки тоже. `source` каждой называет деталь, её автора и лицензию, а страница
показывает подпись под картинками комплекта. Рисунок читается из `.fzpz` на месте и рисуется как изображение, в котором
скрипты не выполняются.

## import_libraries.py

Составляет список известных библиотек в `catalog/libraries/libraries.json`, это ведущий список: Arduino из `library_index.json`,
ESP-IDF из каталога, зависимостей пакетов и поиска по GitHub. У каждой одна запись с чипами, которые она называет, а библиотека
без чипов остаётся библиотекой: она может делать алгоритм и ничем не управлять. `chip_libraries.json` рядом это индекс от чипа к
этому списку, он не обязан покрывать его целиком. Нужен `gh` с входом в аккаунт.

```sh
python3 tools/import_libraries.py library_index.json.gz --date 2026-11-01
```

Список идёт по именам, инструмент ничего не ранжирует. Звёзды и даты показываются и ничего не решают. Большинство этих
библиотек связано с чипом только именем, их никто не читал. Реестр Espressif закрывает свой API от роботов, его не обходим.

## import_addresses.py

Записывает адреса I2C чипов в `imported/devices/` как `address_try`, первым идёт адрес, с которым чип приходит. Запускается
после `import_fritzing.py`, который переписывает эту папку, и после `import_libraries.py`: его список говорит, какие клоны читать.

```sh
python3 tools/import_addresses.py --list
python3 tools/import_addresses.py --esphome esphome/components --libraries CLONES --date 2026-11-01
```

Источники: Python-код ESPHome и заголовки библиотек с разрешительной лицензией, в папках вида `owner__repo`. Читается только
текст. Пакеты плат источником не служат: в них адреса в 8-битной записи, а `import_board_manager.py` сдвигает адреса своих плат.
Что отверг фильтр, попадает в `imported/report_addresses.json`. `--compare` печатает расхождения с таблицей Tasmota: она под
GPL, поэтому остаётся проверкой и никуда не записывается.

Список может быть неполным, поэтому совпадение таких адресов для решателя это неизвестность, а не отказ.

## audit.py

Хранит то, что аудит нашёл в библиотеке, в `audit.json` рядом с её записью: по записи на каждый прочитанный коммит.

```sh
python3 tools/audit.py take esp-idf/jef-sure/pn532 RESULT --src COPY --rubric pn532 --rubric-version 1 --commit SHA --by WHO --version 0.7.6 --tag v0.7.6 --blind
python3 tools/audit.py changes esp-idf/jef-sure/pn532 --clone CLONE --to v0.7.7
python3 tools/audit.py carry esp-idf/jef-sure/pn532 READING --src COPY --clone CLONE --to v0.8.0 --commit SHA --by WHO --version 0.8.0 --tag v0.8.0 --blind
```

`take` проверяет, что каждая цитата результата стоит в прочитанной копии, и оставляет файл со строкой: вместе с коммитом они
говорят то же самое, а чужой код не попадает в этот репозиторий. `changes` сравнивает последнюю запись с новым коммитом, а без
`--to` с рабочим деревом клона, и перечисляет, что читать заново: записи, чьи строки изменились, записи, в чьём файле изменилось
другое, и новые файлы. У `no` нет строки для сравнения, поэтому новый код может изменить любой такой пункт. Клон только читается. `carry` делает запись
нового коммита из последней: то, что стоит на неизменённых строках, остаётся со сдвинутыми номерами, чтение изменённого заменяет
остальное, а если затронутое не перечитано, инструмент отказывает.

## boards_mcp.py

Ставит агента человека рядом со страницей. Работает как MCP-сервер клиента, отдаёт страницу на 127.0.0.1 и ключа не требует:
модель это агент, который его запустил. Один раз, чтобы отдать его агенту:

```sh
python3 tools/boards_mcp.py --install
```

Если на машине есть команда `claude`, сервер получает Claude Code во всех папках (`claude mcp add -s user`). Если нет,
команда пишет `.mcp.json` в текущую папку, рядом с уже записанными там серверами, и печатает ту же запись для клиента,
который держит её в другом месте. Пути полные, поэтому неважно, в какой папке работает агент. Потом перезапусти агента
и попроси его помочь подобрать железо для устройства.

Агент даёт человеку ссылку с токеном. На этой странице появляется диалог, он с первой реплики занимает колонку ролей, а поиск ролей остаётся: модель читает описание, блоки и лучшие комплекты,
ставит блоки с вариантами и деталями, то есть условия решателя, и пишет описание, которое проект хранит как `DESCRIPTION.md`.
Что человек закрепил, то его: булавка на блоке, деталь, выбранная в блоке, или кнопка `pin this board` на карточке. Сервер отказывает
модели в изменении закреплённого, страница отказывает ещё раз, а решатель держит закреплённую деталь за её блоком и пробует только
закреплённую плату. Поле сверху это тема, от которой отталкивается модель, а диалог её развивает: изменённая тема приходит к модели со следующим ответом `wait_for_person`. Решатель остаётся
на странице. Страница, открытая иначе, диалога не показывает и работает как раньше.

## sync_versions.py

```sh
python3 tools/sync_versions.py
```

Заполняет `versions` в записях библиотек `esp-idf`: из реестра компонентов — с чем собирается и что требует каждая версия, из тегов git — версии, которых в реестре нет.
Версия, которой в реестре ещё нет, остаётся как записана.

## Страница

`editor/index.html` показывает, что собрать и на чём, и правит файлы каталога. Ей не нужны ни сборка, ни
сеть, только статический сервер из корня репозитория: Live Server из VS Code или

```sh
python3 -m http.server 8000
```

### select

Форма строится из `catalog/questions.json`. Каждая плата каталога сразу получает ответ: что на ней
есть, каких модулей не хватает и как их подключить, цена и то, чего нет в данных, с пометкой `?`.
Неподходящие платы показаны с причиной. Решатель только предлагает: каждый комплект — это проект, и
решают проверки инструментов. Поэтому два PN532 сами уходят на SPI: правила не пускают один адрес
I2C дважды.

Блок спрашивает данные своей детали вопросами своей роли: у вопроса есть `limit.field`, путь к значению в данных детали с
учётом её варианта, и `limit.fits`, способ сравнения с ответом (`up_to`, `down_to`, `at_least`, `at_most`, `includes`, `is`),
например `co2_up_to` по `provides.air.specified`. Ответ хранится в `asks` блока, поэтому два блока температуры, комната и
печь, спрашивают разные диапазоны и становятся двумя потребностями. Деталь, в данных которой такого значения нет, остаётся,
а комплект называет это неизвестной. Меряемый вопрос класса с `"asked": "block"` тоже задаётся каждому блоку, как
дальность чтения и карты считывателя, диагональ и форма графического дисплея, выходы цепочки: два считывателя
спрашивают своё, а два блока одной роли — это всегда две детали. `limit.of` и `limit.variant` у него могут быть
списками, и блоку без выбранного варианта задаются вопросы любого из них. Расстояние между считывателями остаётся одним
вопросом страницы. Из двух дисплеев из модулей основным становится первый по порядку блоков. Страница показывает эти поля в блоке, модель ставит их через `edit_blocks`, а `roles`
их перечисляет. Платформа спрашивается без версии: комплект называет версии, которые берут его чип и его библиотеки, а
версия закрепляется, только если человек её выбрал.

Решатель подключает I2C, SPI, QSPI и UART и линии, которые нужны чипу помимо шины, например BUSY и
RST у PN5180. Модуль на DSI занимает свободную шину DSI платы шлейфом, а его тайминги остаются
неизвестной комплекта: их меряют на плате. Решатель берёт свободные пины, которые выходят на разъём,
и не трогает пины начальной конфигурации, флеша и консоли. К шине платы он подключается, только если
её линии выходят наружу и её не держит дисплей, и эти линии тоже показывает. Для каждого модуля он
выбирает самую низкую подходящую линию питания из выходящих наружу и просит преобразователь уровней,
если линии модуля поднимаются выше того, что выдерживают ножки чипа, см.
[Питание и уровни](data-format.md#питание-и-уровни). Токи он не суммирует.

Тон и PWM — это выходы чипа: у каждого своя частота, у тона допуск и джиттер, у PWM разрядность скважности, и
любой может меняться на ходу. Решатель перебирает источники чипа в порядке `frequency_sources`, считает для
каждого достигнутую частоту и берёт первый подходящий: обычно LEDC, затем MCPWM и RMT, кварц платы через CLK_OUT,
I2S с APLL. Частота принадлежит таймеру, поэтому выходы с одной настройкой делят таймер. Цифры расчётные, не
измеренные.

Комплекты идут в таком порядке: подходящие, меньше неизвестных, дешевле то, что есть на плате и о чём не просили
(камера, тач, Ethernet; не кнопка на стяжечном пине), меньше модулей, меньше проводов,
затем цена. Бюджет делает цену критерием: тогда она идёт сразу за неизвестными, а отсутствие цены
считается неизвестным. Деталь платы стоит наименьшую цену своего чипа за штуку, из `price` его записи в `catalog/devices`,
умноженную на её `config.count`. Деталь, которая не называет чипа с ценой, весит самый дешёвый чип каталога с её ролью и вариантом,
как `led_smd`, `led_rgb_5050` и `ws2812b`; если таких нет, самый дешёвый модуль её роли и варианта, иначе роли, класса или всех,
за штуку. Нулевая цена — не цена, и деталь весит не меньше цента: бесплатного не бывает.
Модули с ценами из `imported-shops/` в репозиторий не входят, поэтому одинаковый порядок везде даёт
только чип с ценой. `tools/check_format.py` отдаёт комплекты из `test/solver/` ещё и генератору.

`make a project…` спрашивает папку, и от неё зависит, что произойдёт:

- пустая папка или папка, где есть только `.git`, README, лицензия и `.gitignore`, получает весь
  проект. То, что там уже лежит, остаётся;
- папка с `CMakeLists.txt` считается программой и получает только свою плату в
  `components/local-boards/`;
- любая другая папка отвергается.

Сначала показывается список того, что произойдёт, и до кнопки `write` ничего не пишется. Файл платы,
который отличается, заменяется только по галочке, и ничего никогда не удаляется. Если после списка
какой-то файл изменился, не пишется ничего. Комплекту без модулей
файл платы не нужен: проект называет плату каталога. Страница не связывается с GitHub: результат
— папка, а дальше git или ничего.

Плата выбирается до первой сборки, потому что зависимости определяются тем, что на ней есть:
`board_select.py`, затем `idf.py build`. В проекте, собранном для другой платы, нужен
`idf.py reconfigure build`; `board_select.py` об этом скажет.

### edit

`open a folder` принимает программу или её `components/local-boards`, чтобы править платы этой программы. Принимает и папку репозитория:
тогда Chromium сохраняет прямо в каталог. Страницу, открытую из файла, некому обслужить, поэтому там
сначала нужен репозиторий.

Слева список документов каталога, рядом дерево открытого. `card` показывает поля узла и то, что
схема говорит о каждом: написанное в файле обычным текстом, унаследованное серым. Значение,
введённое поверх унаследованного, попадает в этот файл. В файле с `extends` крестик на
унаследованном поле пишет `null`: поле убирается здесь, а база остаётся как есть. `pins` — карта
GPIO, `json` — файл в том виде, как он сохранится, и собранная плата, как её читают инструменты.

Каждое изменение проходит те же проверки, что и в инструментах: схему, загрузчик, правила и карту
пинов. Проблемы перечислены над карточкой. Chromium сохраняет в открытую папку; без неё или в другом
браузере страница отдаёт файл, и его надо положить на место руками. Затем запустите
`tools/boards_gen.py --all`, а для платы программы `tools/board_select.py`.

Платы программы показаны отдельно, поверх каталога, и новое попадает туда. Без программы новый
документ попадает в каталог, поэтому `project` не предлагается.

Файлы `catalog/mcu/` пишет `tools/make_mcu.py`, поэтому здесь они только для чтения. Так же и часть
модуля на плате: её правят в модуле или через `modules` платы.

`tools/check_format.py` сверяет `editor/schema.js`, `editor/pins.js` и JSON, который сохраняет
страница, с инструментами на Python: на всех документах и на их испорченных копиях.
